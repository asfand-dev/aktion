Advanced

Inline JavaScript.

When you need browser APIs the declarative surface doesn’t cover — clipboard writes, IntersectionObserver, third-party SDKs — write JavaScript directly in your function or effect bodies. You get full async access to state, host tools, and the host element via the ctx bridge.

Where you can use it

JavaScript code — including ctx bridge calls — is valid in any imperative body:

  • Inside a function body (action handler).
  • Inside an effect body.
  • Inside a multi-statement lambda body (rare; prefer named functions).

No wrapper syntax is needed — JS code goes directly in the body:

function copyShareLink() {
  await navigator.clipboard.writeText(window.location.href)
  ctx.state.set("copied", true)
}

effect(() => {
  const onScroll = () => ctx.state.set("scrollY", window.scrollY)
  window.addEventListener("scroll", onScroll, { passive: true })
  ctx.cleanup(() => window.removeEventListener("scroll", onScroll))
}, ["mount"])

The ctx bridge

Function and effect bodies run as async functions with access to a ctx bridge. The body can await anywhere. The surface is intentionally narrow — just enough to bridge the script and the host without leaking the entire runtime.

PropertyTypePurpose
ctx.state.get(name)(name: string) => unknownRead a reactive atom. Pass the bare name without $ — e.g. ctx.state.get("count") reads $count.
ctx.state.set(name, value)(name: string, value: unknown) => voidWrite to a reactive atom. Triggers a re-render.
ctx.cleanup(fn)(fn: () => void) => voidRegister a cleanup callback (effect bodies only). Runs when the effect re-fires or unmounts.
ctx.hostHTMLElementThe host <aktion-app> element — useful for dispatchEvent, attribute reads, or accessing the shadow root.
ctx.toolsRecord<string, fn>Host-registered async tools (set via el.setTools(...)).
ctx.argsRecord<string, unknown>Function/lambda parameters by name — e.g. ctx.args.taskId.

State naming

When reading and writing through ctx.state, drop the sigil: use ctx.state.get("count") to read the $count atom and ctx.state.set("count", 1) to write it.

Common recipes

Clipboard

function copyToClipboard(text) {
  try {
    await navigator.clipboard.writeText(ctx.args.text)
    ctx.state.set("toast", { kind: "success", message: "Copied" })
  } catch (err) {
    ctx.state.set("toast", { kind: "error", message: err.message })
  }
}

File input — read as data URL

function pickAvatar(file) {
  const reader = new FileReader()
  reader.onload = () => ctx.state.set("avatarPreview", reader.result)
  reader.readAsDataURL(ctx.args.file)
}

IntersectionObserver for infinite scroll

effect(() => {
  const sentinel = ctx.host.shadowRoot?.querySelector("[data-sentinel]")
  if (!sentinel) return
  const observer = new IntersectionObserver((entries) => {
    if (entries.some((e) => e.isIntersecting)) {
      const page = ctx.state.get("page") || 1
      ctx.state.set("page", page + 1)
    }
  })
  observer.observe(sentinel)
  ctx.cleanup(() => observer.disconnect())
}, ["mount"])

WebSocket subscription

effect(() => {
  const socket = new WebSocket("wss://example.com/stocks")
  socket.addEventListener("message", (event) => {
    ctx.state.set("ticker", JSON.parse(event.data))
  })
  ctx.cleanup(() => socket.close())
}, ["mount"])

Keyboard shortcut listener

effect(() => {
  const onKey = (e) => {
    if (e.key === "k" && (e.metaKey || e.ctrlKey)) {
      e.preventDefault()
      ctx.host.dispatchEvent(new CustomEvent("toggle-palette", { bubbles: true, composed: true }))
    }
  }
  document.addEventListener("keydown", onKey)
  ctx.cleanup(() => document.removeEventListener("keydown", onKey))
}, ["mount"])

Browser navigation guard

effect(() => {
  const onBeforeUnload = (event) => {
    if (ctx.state.get("isDirty")) {
      event.preventDefault()
      event.returnValue = ""
    }
  }
  window.addEventListener("beforeunload", onBeforeUnload)
  ctx.cleanup(() => window.removeEventListener("beforeunload", onBeforeUnload))
}, ["mount"])

Reading function arguments

When a function receives arguments, they land in ctx.args by name. This is handy for per-row action handlers. 

function deleteTask(taskId) {
  const id = ctx.args.taskId
  const remaining = (ctx.state.get("tasks") || []).filter(t => t.id !== id)
  ctx.state.set("tasks", remaining)
}

// In the UI:
Button("Delete", { action: () => deleteTask(task.id) })

Talking to a host-registered tool

Tools are the right primitive when the host has secrets, signed URLs, or framework-specific APIs the script shouldn’t touch directly. Register them once on the host: 

// Host
el.setTools({
  uploadFile: async ({ file }) => {
    const body = new FormData();
    body.append("file", file);
    const res = await fetch("/api/upload", { method: "POST", body });
    return res.json();
  },
  fetchOrder: async ({ id }) => (await fetch(`/api/orders/${id}`)).json(),
});

Then call them from the script via ctx.tools:

function uploadAvatar(file) {
  const result = await ctx.tools.uploadFile({ file: ctx.args.file })
  ctx.state.set("avatarUrl", result.url)
}

When to use declarative features instead

The declarative surface already covers most needs — prefer it whenever possible:

  • Fetching data — use Http({...}), never fetch().
  • Navigation — use route.navigate(path), never window.location.
  • Persistence — use the storage global directly (storage.set, storage.cookies.set, …).
  • Logging — use console.log(...) directly — it’s an Aktion global.
  • Dispatching events — use emit("name", { detail }) from a function/effect body.
  • Side-effect chaining — use multiple function calls or an effect with a state trigger.

Reach for the ctx bridge and raw browser APIs only when you need a DOM API, a third-party SDK, or a host integration that has no declarative equivalent.

Security notes

  • JavaScript in function/effect bodies is executed with new Function(...). It runs in the host page’s realm, with full access to the page’s globals and DOM.
  • Only feed scripts from trusted sources. If you accept Aktion from arbitrary users, strip or refuse JavaScript code before passing the text to the element.
  • Strict CSP environments may need 'unsafe-eval' for function bodies that use browser APIs to execute. The rest of the runtime works without it.
  • Errors thrown inside function/effect bodies are caught and logged; they never crash the surrounding program.
