UI Providers (Interoperability Layer)

Aktion ships with a robust built-in UI library, but it doesn't lock you in. Using the UIProvider interoperability interface, you can completely swap Aktion's output to generate interfaces using Material UI, Bootstrap, ShadCN, or any other design system.

These connectors are shipped as standalone sibling packages (e.g., @aktion/mui-provider). Aktion parses the logic and state, while the provider maps those instructions into the actual components of your favorite UI library.

Using a UI Provider

To use an external UI library, import its provider and pass it to your <aktion-app> element via setUIProvider().

import { AktionElement } from "aktion";
import { muiProvider } from "@aktion/mui-provider"; // Hypothetical package

const app = document.querySelector("aktion-app");
app.setUIProvider(muiProvider);

// Now, rendering `Button("Click Me")` inside Aktion 
// will output a Material UI <Button> node.

Building a Provider

A UI provider is simply an object implementing the UIProvider interface:

export interface UIProvider {
  name: string;
  library: ComponentLibrary;
  setup?: (root: ShadowRoot | Document | HTMLElement) => void;
  teardown?: () => void;
}

Here's a minimal example showing how you might build an adapter for Bootstrap: 

import type { UIProvider, ComponentLibrary, ComponentSpec } from "aktion";

const bootstrapComponents: ComponentSpec[] = [
  {
    name: "Button",
    description: "A Bootstrap button",
    props: [
      { name: "label", type: "string", positional: true },
      { name: "variant", type: "string", enum: ["primary", "secondary", "danger"] }
    ],
    render(node, props, helpers) {
      const btn = document.createElement("button");
      btn.className = `btn btn-${props.variant || "primary"}`;
      btn.textContent = props.label as string;
      
      // Wire up Aktion events to standard DOM events
      if (props.onClick) {
        btn.addEventListener("click", (e) => helpers.invoke(props.onClick, e));
      }
      return btn;
    }
  }
];

export const bootstrapProvider: UIProvider = {
  name: "Bootstrap",
  library: {
    root: "Container",
    components: bootstrapComponents
  },
  setup(root) {
    // Inject Bootstrap CSS into the Aktion shadow root
    const link = document.createElement("link");
    link.rel = "stylesheet";
    link.href = "https://cdn.jsdelivr.net/npm/bootstrap@5.3.0/dist/css/bootstrap.min.css";
    root.appendChild(link);
  }
};

Integrating React libraries (like MUI)

Since React components don't return plain DOM nodes, your provider can render a React root into a container div: 

import { createRoot } from "react-dom/client";
import { Button as MuiButton } from "@mui/material";

export const muiProvider: UIProvider = {
  name: "MUI",
  library: {
    root: "Box",
    components: [
      {
        name: "Button",
        description: "MUI Button",
        props: [{ name: "label", type: "string", positional: true }],
        render(node, props, helpers) {
          const container = document.createElement("div");
          container.style.display = "inline-block";
          
          const root = createRoot(container);
          root.render(
            <MuiButton onClick={() => helpers.invoke(props.onClick)}>
              {props.label as string}
            </MuiButton>
          );
          
          helpers.registerDisposer(() => root.unmount());
          return container;
        }
      }
    ]
  }
};

Writing your own packages

To distribute a UI Provider for an in-house framework or a public UI library, the best approach is to package it as a standalone npm module. Here is how to structure and write your own packages:

  1. Map Aktion components: Create a one-to-one mapping between Aktion's standard components (e.g., Button, Card, Row) and the target library's counterparts.
  2. Implement the interface: Define an object conforming to the UIProvider interface. Provide an array of ComponentSpec objects mapping Aktion props to your framework's expected properties.
  3. Handle lifecycle and context: Use the setup(root) and teardown() methods of the UIProvider to inject required CSS variables, styles, font links, or context providers (e.g. React Providers) into the DOM.
  4. Export the provider: Expose the fully configured provider from your package entry point (e.g. export const myFrameworkProvider = { ... }).

As an example, if you build an adapter for your company's internal design system, you could publish it as @your-org/aktion-provider. Your users will then only need to call app.setUIProvider(yourOrgProvider) to completely restyle their Aktion applications.
