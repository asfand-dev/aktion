Built-in

Actions.

Every interactive control in Streaming UI Script — buttons, follow-ups, sidebar items, even keyboard shortcuts — runs an Action([...]) payload. Actions are the bridge between the rendered UI and the reactive runtime: they write state, run queries and mutations, navigate, fire follow-ups, open URLs, and (when needed) execute JavaScript.

Action([@step, @step, …])

Sequential step list. Steps execute in order; a failing step short-circuits the rest. Always at least one step.

Where it goes

Drop into Button, NavbarItem, SidebarItem, FollowUpItem, Form submit, and any other prop that takes action.

Always declarative first

Reach for @Set + @Push / @Filter / @Sort before @Js. Most "imperative" UI is a pure data transform.

Actions are part of the runtime

Every <streaming-ui-script> renderer wires up actions automatically — no attribute to flip. The default ("full") system prompt teaches the model the entire step menu; the chat-flavoured prompt (getSystemPrompt({ mode: "chat" })) keeps a minimal subset (@ToAssistant, @OpenUrl) for purely conversational replies.

1. The full step menu

Seven action steps cover every interaction shape the LLM should reach for. Steps are @-prefixed marker calls that the runtime interprets at click time — they are not evaluated when their containing component renders.

StepEffectUse for
@Set($name, value) Write $name = value. value is evaluated at click time, so it can read other state freely. Local UI state — toggles, drafts, filters, selected ids, modal open/close.
@Reset($a, $b, …) Reset each named state to its declared default ($x = 0 means @Reset($x) → 0). Form clear, modal close + reset draft, "back to defaults".
@Run(ref) Execute a Query or Mutation by name. Awaited before the next step. Save a record, refresh a list, kick off a poll.
@ToAssistant("text") Fire an assistant-message CustomEvent with { message: "text" }. Host pages typically forward the message back to the LLM. Follow-up prompts, "ask the assistant" buttons, chat replies.
@OpenUrl("https://…") Open a URL in a new tab (sanitised; noopener,noreferrer). Override via onOpenUrl on the host element. External links from buttons, "open docs", "view on GitHub".
@Navigate("/path") Push a new hash path through the built-in router. Updates window.location.hash; back/forward keeps working. In-app navigation after a save, "back" buttons, programmatic redirects. See the routing guide.
@Js(body, args?) Run an arbitrary JavaScript body. The optional args object is captured at render time and exposed inside the body as ctx.args. One-off side effects (clipboard, focus, audio, animations) and per-row click handlers inside @Each(…). See the JavaScript guide.

2. Quick start: a one-step action

The simplest button: write a single state variable on click. Notice that $open is read by the modal expression, written by the action, and the runtime keeps both in sync without any glue code. 

$open = false

openBtn  = Button("Open dialog", Action([@Set($open, true)]),  "primary")
closeBtn = Button("Close",       Action([@Set($open, false)]), "ghost")

dialog = Modal("Quick action", $open, [
  TextContent("Click anywhere outside or press Esc to close."),
  closeBtn
])

root = Stack([openBtn, dialog])

3. Multi-step actions (the real value)

Steps execute sequentially. Combine them to express a full interaction in one statement — save, then close the modal, then notify the assistant: 

$editing = false

saveBtn = Button("Save & close", Action([
  @Run(saveMutation),
  @Set($editing, false),
  @ToAssistant("Profile saved.")
]), "primary")

Order matters. @Run(saveMutation) is awaited before @Set($editing, false) fires, so the modal stays open while the save is in flight (a spinner state can read the inFlight flag from the mutation).

Failing steps short-circuit

If @Run rejects, the rest of the action is skipped and the error is logged. Use this to your advantage: put the mutation first, then optimistic state writes after — if the server rejects the change, the UI doesn't lie.

4. Default action: send the label to the assistant

Buttons and follow-up items without an explicit Action(…) automatically fire @ToAssistant(label). This makes chat-style replies very compact: every "Tell me more" / "Compare alternatives" button forwards its own label to the LLM. 

follow = FollowUpBlock([
  FollowUpItem("Show me more"),
  FollowUpItem("Explain this"),
  FollowUpItem("Try a different angle")
])

learnMore = Button("Learn more about caching")

These four buttons are equivalent to: 

FollowUpItem("Show me more", Action([@ToAssistant("Show me more")]))
…
Button("Learn more about caching", Action([@ToAssistant("Learn more about caching")]))

5. Wiring forms with actions

A Form(…) takes an array of submit-row Buttons — each one carries its own Action. Pair an "add" button with a FormControl input whose value two-way-binds to a $variable: 

$todos = [{id: 1, text: "Welcome", done: false}]
$draft = ""

addBtn = Button("Add", Action([
  @Set($todos, @Push($todos, {id: $todos.length + 1, text: $draft, done: false})),
  @Reset($draft)
]), "primary")

clearBtn = Button("Clear", Action([@Reset($todos, $draft)]), "ghost")

list = @Each($todos, "t", row)
row = ListItem(t.text, t.done ? "Completed" : "Open", t.done ? "circle-check" : "circle")

root = Stack([
  Card([CardHeader("Mini todo", "Add a task to see actions in action")]),
  FormControl("New task", Input("draft-input", "What needs doing?", "text", null, $draft)),
  Buttons([addBtn, clearBtn]),
  Card([List([list])])
])

Notice how add and clear are purely declarative. No JavaScript — @Push + @Set grows the array, @Reset brings every listed state back to its declared default.

6. Per-row actions inside @Each(…)

The most common Action pattern is a row-level Delete / Toggle / Open inside an iteration. Two strategies, in order of preference:

  • Pure data transform — no JS. Use @Filter + @Set to remove an item; @Sort to re-order; @Concat to prepend.
  • Per-item JS handler. When no builtin can express the change (toggling one field on one item, optimistic edits, animations), use @Js(body, {id: x.id}) and read the captured value as ctx.args.id. 
$todos = [{id: 1, text: "Buy milk", done: false}, {id: 2, text: "Walk dog", done: true}]
list = @Each($todos, "t", row)
row = Card([Stack([
  Badge(t.done ? "done" : "open", t.done ? "success" : "neutral"),
  TextContent(t.text),
  Buttons([
    Button("Toggle", Action([
      @Js(`
        const todos = ctx.state.get('todos') || [];
        ctx.state.set('todos', todos.map(x =>
          x.id === ctx.args.id ? Object.assign({}, x, {done: !x.done}) : x
        ));
      `, {id: t.id})
    ])),
    Button("Delete", Action([
      @Set($todos, @Filter($todos, "id", "!=", t.id))
    ]), "ghost")
  ])
])])

Don't read loop variables from ctx.state

Inside @Each($todos, "t", row), t is a render-time local — not reactive state. ctx.state.get('t') always returns undefined. Always pass the value through @Js's second argument: {id: t.id}.

7. Combining actions with queries and mutations

Query auto-runs and re-runs when its $variable args change. Mutation only runs from @Run(name) inside an Action. The classic save-then-refresh chain looks like this: 

$draft = ""
$ver   = 0

list   = Query("list_tickets", {ver: $ver}, {rows: []})
create = Mutation("create_ticket", {title: $draft})

addBtn = Button("Create ticket", Action([
  @Run(create),               // POST to the server
  @Set($ver, $ver + 1),       // bump the cache key — refetches list
  @Reset($draft),             // clear the form
  @ToAssistant("Created.")    // tell the LLM
]), "primary")

field = FormControl("Title", Input("title", "Bug summary…", "text", null, $draft))
table = Table([Col("Title", list.rows.title), Col("Status", list.rows.status)])

root = Stack([CardHeader("Tickets"), field, addBtn, table])

The $ver trick is the canonical way to force a Query to refetch when no other arg has changed — bumping a counter inside the args object marks a new dependency version.

8. Programmatic navigation with @Navigate

Built-in routing is always wired up. Drop @Navigate("/path") into any action chain to move to another route after a save, submit, or follow-up: 

saveBtn = Button("Save", Action([
  @Run(saveMutation),
  @Navigate("/dashboard"),
  @ToAssistant("Saved — back on the dashboard.")
]), "primary")

cancelBtn = Button("Cancel", Action([@Navigate("/dashboard")]), "ghost")

Hash paths look like #/dashboard in the URL bar. Browser back / forward, deep links, and bookmarks all work without any host-side router. See the dedicated routing guide for the full surface.

9. Opening external URLs safely

@OpenUrl sanitises the URL before opening, so an LLM emitting javascript:, data:text/html, or other unsafe schemes can never execute on click. Every external window is opened with noopener,noreferrer. 

docsBtn = Button("Read the docs", Action([
  @OpenUrl("https://asfand-dev.github.io/streaming-ui-script/")
]), "primary")

repoBtn = Button("Star on GitHub", Action([
  @OpenUrl("https://github.com/asfand-dev/streaming-ui-script")
]), "ghost", "button", "small", "brands:github")

Override how URLs open from the host page (e.g. to log clicks or route through an analytics layer): 

const renderer = document.querySelector("streaming-ui-script");
renderer.onOpenUrl = (url) => {
  trackOutbound(url);
  window.open(url, "_blank", "noopener,noreferrer");
};

10. @Js for the last 5%

Most click handlers are pure data transforms — reach for builtins first. @Js is the escape hatch for everything else: clipboard, focus, audio, animations, third-party SDKs, sub-second timers. 

copyBtn = Button("Copy snippet", Action([
  @Js("await navigator.clipboard?.writeText(ctx.state.get('snippet') ?? '');"),
  @Set($copied, true),
  @ToAssistant("Copied!")
]), "primary")

ctx exposes reactive state, registered tools, DOM refs inside the shadow root, lifecycle hooks, and an AbortSignal. See the dedicated JavaScript interactions page for the full surface.

11. Where actions appear

Anything that the user can click, tap, submit, or pick can carry an action. The component reference lists the exact prop name for each (look for action); these are the most-used slots:

ComponentAction propNotes
Button(label, action?, variant?, …) 2nd arg The canonical action carrier. Falls back to @ToAssistant(label) when omitted.
FollowUpItem(label, message?) built in Always fires @ToAssistant(message ?? label) — you don't pass an explicit Action.
SidebarItem(label, icon?, active?, badge?, action?) 5th arg Click on a sidebar nav row.
NavbarItem(label, to?, href?, icon?, active?, action?) 6th arg Use to for in-app navigation, href for external URLs, or action for a custom handler.
MenuItem(label, action?, icon?, shortcut?, variant?, disabled?) 2nd arg Inside a DropdownMenu. Set variant="danger" for destructive items.
Form(name, buttons, fields) buttons array Each Button in the row has its own Action.
Tile(label, icon?, value?, description?, tone?, action?) 6th arg Whole tile becomes clickable when action is set.
Banner / Notification action button Pass a Button as the action slot — that Button carries the action.

12. Worked example: edit-in-place with optimistic update

A more realistic flow: pick an item from a list, edit it in a modal, save through a mutation, refresh the list, close the modal. Every interaction is a single Action chain. 

$selectedId = null
$editing    = false
$draft      = ""
$ver        = 0

list = Query("list_tasks", {ver: $ver}, {rows: [
  {id: 1, title: "Wire up CI",     status: "open"},
  {id: 2, title: "Refactor parser",status: "doing"},
  {id: 3, title: "Ship docs site", status: "done"}
]})
save = Mutation("update_task", {id: $selectedId, title: $draft})

rows = @Each(list.rows, "t", taskRow)
taskRow = Card([Stack([
  Badge(t.status, t.status == "done" ? "success" : (t.status == "doing" ? "primary" : "neutral")),
  TextContent(t.title),
  Button("Edit", Action([
    @Set($selectedId, t.id),
    @Set($draft,      t.title),
    @Set($editing,    true)
  ]), "ghost", "button", "small")
], "row", "m", "center")])

editor = Modal("Edit task", $editing, [
  FormControl("Title", Input("draft", "Task title", "text", null, $draft)),
  Buttons([
    Button("Save", Action([
      @Run(save),
      @Set($ver, $ver + 1),
      @Set($editing, false),
      @ToAssistant("Updated.")
    ]), "primary"),
    Button("Cancel", Action([@Set($editing, false), @Reset($draft)]), "ghost")
  ])
])

root = Stack([CardHeader("Tasks"), rows, editor])

Five actions, each a one-liner: open sets three state variables; save mutates, refetches, closes the modal, notifies the assistant; cancel closes and resets. The list re-renders automatically when $ver bumps the query dependency.

13. Best practices

  • Default to declarative. If Action([@Set, @Run, @Reset, @Push, @Filter, @Sort]) can express the change, use it. Reach for @Js only when no builtin can express the mutation.
  • Order matters. Steps run sequentially. @Run is awaited — following steps see the post-mutation state.
  • Reset what you set. If a button opens a modal (@Set($open, true)), the close path should @Reset any draft state so the next open starts clean.
  • Use the implicit @ToAssistant. For "ask the assistant" buttons, omit Action(…) entirely — the label becomes the message.
  • Pass per-row data through @Js args, never through state. Loop variables are render-time locals. @Js(body, {id: t.id}) is the canonical pattern.
  • Bump a version counter to refetch. When a mutation's effect isn't reflected in any query argument, add {ver: $ver} to the query args and @Set($ver, $ver + 1) after the mutation.
  • Sanitise URLs through @OpenUrl. Never bypass it with @Js("window.location = …") — you lose the runtime's URL allow-list.

14. Common mistakes

Don'tDo
Action([@Set($x, 1) @Run(save)]) — missing comma. Action([@Set($x, 1), @Run(save)]) — comma-separated.
Action([@Run(save) Enthusiastic]) — stray word. Action arrays contain ONLY action steps. No prose, no labels.
Action([@Js(`ctx.state.set('todos', ctx.state.get('todos').concat(item))`)]) Action([@Set($todos, @Push($todos, item))]) — no JS needed.
Button("Go", "@Run(save)") — passing the step as a string. Button("Go", Action([@Run(save)])) — always wrap in Action([…]).
@Js("ctx.state.set('t.id', …)") reading a loop var as state. @Js(body, {id: t.id}), then ctx.args.id inside the body.
@OpenUrl("javascript:alert(1)") — the runtime collapses this to #. Only allow-listed schemes (http(s), mailto, tel, fragments, root-relative).
Action([@Set($route, "/x")]) — $route is owned by the router. Action([@Navigate("/x")]) — the only correct way to push a route.

15. chat mode actions

The compact prompt flavour (getSystemPrompt({ mode: "chat" })) keeps the action surface minimal so chat replies stay declarative. In chat mode the LLM only sees:

  • @ToAssistant("text") — conversational follow-ups.
  • @OpenUrl("https://…") — external links.
  • The implicit-label fallback for buttons without an explicit Action.

State writes, queries, mutations, navigation, and JS are intentionally hidden — the chat prompt is a strict subset focused on streaming, conversational UIs. Switch back to the full prompt (getSystemPrompt()) for app-style replies that need state, queries, routing, or JavaScript.

16. JavaScript bridge

Want to trigger an action from JS — e.g. a global keyboard shortcut, a host-page button, or a unit test? Reach for the navigate method on the element (for @Navigate), or fire your own @ToAssistant via the chat host:

Action stepEquivalent host call
@Navigate("/x") el.navigate("/x")
@ToAssistant("hi") el.dispatchEvent(new CustomEvent("assistant-message", { detail: { message: "hi" } }))
@OpenUrl("https://…") window.open("https://…", "_blank", "noopener,noreferrer")
@Set / @Reset Inside a Script / @Js body: ctx.state.set(name, value), ctx.state.reset(…names).
