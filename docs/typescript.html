Guide

TypeScript guide.

The .aktion DSL itself is untyped, but everything around it — the host element, custom components, interceptors, and event payloads — ships full type declarations. This guide shows how to wire Aktion into a typed host with no any leaks.

Scope. Types cover the integration surface (the code you write in TypeScript around <aktion-app>). The program text the runtime renders is a JS-subset DSL and is not type-checked — see Language.

Install the package and you get the type declarations for free — there is no separate @types package to add: 

npm install aktion-runtime
# types ship in the package; no @types/* needed

Typing the host element

<aktion-app> is a custom element. Cast the result of document.createElement / querySelector to the exported element type so the streaming methods and properties are typed: 

import type { AktionElement } from "aktion-runtime";
import "aktion-runtime"; // registers the element

const app = document.querySelector("aktion-app") as AktionElement;
app.setResponse(source);     // full document
app.appendChunk(tokenDelta); // streaming tail
app.setAttribute("theme", "dark");

Host event payloads

The element dispatches typed CustomEvents. Type the detail when you add listeners:

Eventdetail shape
assistant-message{ message: string } — the app asked the host to send a message back to the LLM.
route-change{ path: string } — the router navigated.
error{ errors: { line: number; column: number; message: string }[] }.
 
app.addEventListener("assistant-message", (e) => {
  const detail = e.detail as { message: string };
  sendToModel(detail.message);
});

app.addEventListener("error", (e) => {
  const detail = e.detail as { errors: { line: number; column: number; message: string }[] };
  detail.errors.forEach((err) => reportError(err));
});

To stop casting e.detail at every call site, define a small typed map of the events and a generic on(…) helper. You get autocompletion on the event name and a correctly-typed detail: 

interface AktionEventMap {
  "assistant-message": { message: string };
  "route-change": { path: string };
  "error": { errors: { line: number; column: number; message: string }[] };
}

function onAktion<K extends keyof AktionEventMap>(
  el: EventTarget,
  type: K,
  handler: (detail: AktionEventMap[K]) => void,
): () => void {
  const listener = (e: Event) => handler((e as CustomEvent<AktionEventMap[K]>).detail);
  el.addEventListener(type, listener);
  return () => el.removeEventListener(type, listener); // call to unsubscribe
}

// detail is typed as { message: string } — no cast, no `any`.
const off = onAktion(app, "assistant-message", (detail) => sendToModel(detail.message));

Typing custom components

A custom built-in is a ComponentSpec. Its render receives the node, resolved props, and the typed helpers surface. Register it with registerComponents: 

import "aktion-runtime";
import type { AktionElement, ComponentSpec } from "aktion-runtime";

const Sparkline: ComponentSpec = {
  name: "Sparkline",
  description: "Inline trend line.",
  props: [
    { name: "values", type: "number[]", positional: true, required: true },
    { name: "stroke", type: "string", optional: true },
  ],
  render: (_node, props, helpers) => {
    const values = (props.values as number[]) ?? [];
    const el = document.createElement("svg");
    // ...build the SVG from `values`...
    return el;
  },
};

const app = document.querySelector("aktion-app") as AktionElement;
app.registerComponents([Sparkline]); // next getSystemPrompt() includes it

The helpers object is fully typed — renderNode, invoke, setState, useInstanceState, registerDisposer, and router all carry signatures, so authoring a spec stays type-safe.

Typing interceptors & the language surface

The DOM-free aktion-runtime/language entry exports getDiagnostics, getCompletions, getHoverInfo, and formatProgram (with its FormatResult type) for building editor tooling or CI lint steps without a browser: 

import { getDiagnostics, formatProgram } from "aktion-runtime/language";

const diagnostics = getDiagnostics(source); // Diagnostic[]
const { formatted } = formatProgram(source); // idempotent pretty-print

import { renderToString, componentSchema, tailwindToSx } from "aktion-runtime";

const { html, state } = renderToString(source, { path: "/" });
const schema = componentSchema();            // for editor tooling
const sx = tailwindToSx("p-4 bg-white rounded-lg shadow"); // → { p: "m", bg: "surface", ... }

The Testing entry (aktion-runtime/test) additionally exports within(node) for scoped queries and axe(node) for an accessibility audit — both typed (see the Testing guide).

A typed host-wrapper recipe

A small typed wrapper centralises streaming and event wiring for any framework host: 

import "aktion-runtime";
import type { AktionElement } from "aktion-runtime";

export interface AktionHost {
  el: AktionElement;
  stream(delta: string): void;
  reset(full: string): void;
  dispose(): void;
}

export function mountAktion(parent: HTMLElement): AktionHost {
  const el = document.createElement("aktion-app") as AktionElement;
  parent.appendChild(el);
  const onError = (e: Event) => {
    const detail = (e as CustomEvent).detail as { errors: { message: string }[] };
    detail.errors.forEach((x) => console.error("[aktion]", x.message));
  };
  el.addEventListener("error", onError);
  return {
    el,
    stream: (delta) => el.appendChunk(delta),
    reset: (full) => el.setResponse(full),
    dispose: () => { el.removeEventListener("error", onError); el.remove(); },
  };
}
