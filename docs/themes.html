Theming

Themes.

Aktion ships with polished built‑in themes — switch between them with one attribute on <aktion-app>. Need a brand of your own? Override any design token in‑program with $theme({…}): colors, radius, typography, motion. No raw CSS, no stylesheet plumbing — just a token map.

Built-in themes

Seven themes come in the box. Select one with the theme attribute on the host element: light (default), dark, neon, pastel, glass, brutalist, and skyline. Switching is instant — a theme is just a set of CSS custom properties written to the host, so it never re‑renders your tree. 

<aktion-app theme="dark"></aktion-app>
ThemeFeel
lightDefault. Crisp white surfaces, indigo accent.
darkStandard high‑contrast dark surface.
neonCyberpunk glow — magenta/cyan, monospace headings, sharp corners.
pastelSoft & rounded — lavender + mint, large radii.
glassFrosted glass — translucent surfaces over a vivid gradient.
brutalistNeo‑brutalism — hard 2px borders, chunky offset shadows, all‑caps headings.
skylineCloud‑console — deep navy + cyan, dense layout, small radii.

This docs site has its own light/dark toggle in the top bar — the live demos below follow it, so you can see how the same tokens read on either background.

Custom tokens with $theme({…})

Assign $theme({…}) to a top‑level binding named theme (alongside your aktion root). The runtime detects it, writes those tokens to the host as CSS custom properties, and reskins the rest of the UI instantly. Tokens live in groups: override just colors.primary and every button, badge, link, and focus ring follows.

Live 
theme = $theme({ colors: { primary: "#7c3aed", primaryHover: "#6d28d9" } })
aktion = Column([
  Card([
    CardHeader("Purple brand", { subtitle: "Only colors.primary changed" }),
    Row([
      Button("Primary", { variant: "primary" }),
      Button("Ghost", { variant: "ghost" }),
      Badge("New", { tone: "primary" })
    ], { gap: "s" })
  ])
], { gap: "m" })

Combine groups. Here colors plus radius give a mint‑accented look with a bigger card radius and fully‑rounded buttons:

Live 
theme = $theme({
  colors: { primary: "#0d9488", primaryHover: "#0f766e", accent: "#f59e0b" },
  radius: { md: "18px", button: "999px" }
})
aktion = Column([
  Card([
    CardHeader("Mint & rounded"),
    Text("Bigger card radius, pill-shaped buttons."),
    Row([
      Button("Save", { variant: "primary" }),
      Button("Cancel", { variant: "secondary" }),
      Badge("Beta", { tone: "warning" })
    ], { gap: "s" })
  ])
], { gap: "m" })

Typography is a group too. Override font.family and font.familyHeading for a different voice — here a serif editorial look with a crimson accent and sharp corners:

Live 
theme = $theme({
  colors: { primary: "#dc2626", primaryHover: "#b91c1c" },
  font:   { family: "Georgia, 'Times New Roman', serif", familyHeading: "Georgia, serif" },
  radius: { md: "2px", button: "2px" }
})
aktion = Column([
  Card([
    CardHeader("Editorial", { subtitle: "Serif type, crimson accent, sharp corners" }),
    Text("$theme({...}) overrides only the tokens you pass — everything else inherits the host theme."),
    Row([Button("Read more", { variant: "primary" }), Badge("Featured", { tone: "danger" })], { gap: "s" })
  ])
], { gap: "m" })

Token groups

Inside $theme({…}) the top‑level keys are structured groups. Each group's camel‑case keys flatten predictably: colors.primary → colorPrimary, radius.md → radiusMd, font.familyHeading → fontFamilyHeading.

GroupExample keysControls
colorsprimary · primaryHover · accent · bg · surface · text · border · success · warning · danger · focusRingSurface, brand, semantic, and focus‑ring colors.
radiusxs · sm · md · lg · pill · button · inputCorner rounding per element class.
fontfamily · familyHeading · familyMono · sizeBase · weightBody · weightHeadingType families, sizes, weights, and heading treatment.
motion…Transition timing shared by hover / focus animations.
elevation…Shadow depth for raised surfaces.

Two metadata keys are also accepted at the top level: name and direction. They are never emitted as CSS variables. Flat‑shape tokens (colorPrimary) and free‑form CSS variables raise a schema warning inside $theme({…}) and are dropped — always use the structured groups here.

Per-response vs host theme

There are two layers. The host picks a base with the theme="…" attribute (one of the seven built‑ins). A program can then layer a per‑response override on top by binding theme = $theme({…}) — it applies only the tokens you pass, so everything else still inherits the host theme. The in‑program $theme({…}) wins for the tokens it sets; remove the line and the UI snaps back to the host theme. Because the override is scoped to that single <aktion-app> embed, themes never leak across responses — the previous tokens are cleared before the next render applies its own.

Dark mode

There is a first‑class built‑in dark theme — no token authoring required. Set it on the host and your whole tree picks up the dark surfaces, text, borders, and shadows: 

<aktion-app theme="dark"></aktion-app>

You can still layer a per‑response $theme({…}) on top of dark to brand it — e.g. override colors.primary while keeping the dark surfaces underneath.
