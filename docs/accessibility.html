Accessibility.

LLM-generated UI is high-stakes for accessibility — the markup is produced for the user, not hand-audited. Aktion bakes accessible semantics into its components so generated output is usable by keyboard and screen reader by default. This page documents what’s built in and how to keep your own additions conformant.

Conformance target

Components target WCAG 2.1 AA semantics: meaningful roles, accessible names, keyboard operability, and visible focus. The runtime renders into a shadow DOM, so component-provided ARIA travels with the element and is exposed to assistive technology like any native control.

Conformance is a property of the final page, not just the library. Custom themes, custom components, and the surrounding host page all affect it — use the checklist at the end to verify your build.

What you get for free vs. what you own

The library handles: roles, accessible names, focus order, focus trapping in Modal, live-region announcements, reduced-motion, forced-colors, and RTL. You still own: custom component semantics, custom-theme contrast, and meaningful alt text / labels on the content you generate. The axe() audit and the pre-ship checklist catch the rest.

ARIA built into components

ComponentAccessibility behaviour
ModalSets aria-modal and aria-labelledby (from its title), traps focus within the dialog, restores focus to the trigger on close, and closes on Esc.
ToastUses role="alert" for the danger tone (assertive) and role="status" otherwise (polite), so notifications are announced appropriately.
NavLinkMarks the active route with aria-current="page".
Buttons & controlsRender as real interactive elements with accessible names, focusable in tab order with visible focus styling.
Form controlsFormControl associates labels, help text, and error messages with their input.

Keyboard map

KeyAction
Tab / Shift+TabMove focus forward / backward through interactive elements. Inside a Modal, focus wraps within the dialog.
Enter / SpaceActivate the focused button or control.
EscClose the open Modal (focus returns to the trigger).
Arrow keysMove within composite widgets (tabs, menus) where applicable.

Screen readers & streaming

Because UI streams in token-by-token, content can change rapidly. To keep the experience calm for assistive tech:

  • The morph reconciler patches the DOM in place rather than replacing it, so focus, selection, and a screen reader’s reading position survive re-renders.
  • Status changes use polite/assertive live regions via Toast roles — reserve the assertive danger tone for errors that must interrupt.
  • Prefer revealing a region once its content has settled (e.g. an Async/Lazy fallback) over announcing every intermediate token.

Theme contrast

The built-in light and dark themes are designed for readable text/background contrast. When you author a custom theme with $theme({...}):

  • Keep body text at 4.5:1 contrast against its background and large text / UI affordances at 3:1.
  • Never encode meaning with colour alone — pair tone with an icon or text label (the components already do this for status).
  • Verify focus indicators remain visible against your custom surfaces.

Keeping custom components accessible

Avoid — a styled div has no role or keyboard support
OnClick(
  Box([Text("Delete")], { padding: "sm" }),
  { onClick: () => remove() }
)
Prefer — a real button is focusable & named
Button("Delete", {
  variant: "danger",
  icon: "trash",
  onClick: () => remove()
})
  • Build from real interactive elements (button, a, input) rather than click-handler divs.
  • Give every control an accessible name (visible label, aria-label, or aria-labelledby).
  • Use $id to generate unique ids for label/description associations instead of hard-coding them.
  • Manage focus for anything that opens/closes (mirror Modal: trap while open, restore on close).

Accessibility primitives

Four components cover the most common screen‑reader and focus‑management needs. They render the right ARIA and behaviour so you don’t hand‑roll it.

ComponentWhat it does
VisuallyHidden(child)Hides content visually but keeps it in the accessibility tree — for extra context a sighted user doesn’t need.
SkipLink({ to, label })A “skip to main content” link that appears on focus — the first thing a keyboard user tabs to.
LiveRegion(text, { politeness, visible })An aria-live region. politeness: "polite" (default) or "assertive" announces dynamic changes; set visible: true to also show it on screen.
FocusTrap(child, { active })Cycles Tab within its subtree and autofocuses the first control — the mechanism behind accessible dialogs. active defaults to true.
 
$app(Column([
  SkipLink("#main", { label: "Skip to content" }),
  Button("Save", { onClick: () => { save(); $status = "Saved" } }),
  LiveRegion(`Status: ${$status}`, { politeness: "polite" }),  // announced to screen readers
  VisuallyHidden(Text("Press Escape to close")),
]))
Live — the status text is announced politely to screen readers 
$status = "Nothing saved yet"
$app(Column([
  SkipLink("#main", { label: "Skip to content" }),
  Button("Save", { variant: "primary", onClick: () => { $status = "Saved just now" } }),
  LiveRegion(`Status: ${$status}`, { politeness: "polite" }),
  VisuallyHidden(Text("This sentence is read by screen readers but hidden visually.")),
], { gap: "md" }))

FocusTrap — confine keyboard focus

Wrap any subtree in FocusTrap while it is open and Tab / Shift+Tab cycle within it instead of escaping to the page behind. It autofocuses the first control on mount, so it’s the right primitive for hand‑rolled dialogs, drawers, and command palettes. (Modal already traps focus, so reach for FocusTrap only when you build the overlay yourself.) Bind active to the open state so the trap engages only while the surface is visible: 

$open = false
$app(Column([
  Button("Open panel", { variant: "primary", onClick: () => { $open = true } }),
  $open ? FocusTrap(
    Card([
      CardHeader("Edit profile"),
      Input("name", { placeholder: "Name" }),
      Input("email", { placeholder: "Email" }),
      Row([
        Button("Cancel", { onClick: () => { $open = false } }),
        Button("Save", { variant: "primary", onClick: () => { $open = false } }),
      ], { gap: "sm" }),
    ]),
    { active: $open }
  ) : null,
], { gap: "md" }))

RTL & logical layout

Set dir on the host <aktion-app> element to flip the whole tree for right‑to‑left languages. The runtime reflects it onto the render root, so direction and CSS logical properties mirror text, flex order, and logical spacing automatically. 

<aktion-app dir="rtl"></aktion-app>
<!-- "rtl" | "ltr" | "auto" -->

Because spacing and layout primitives use logical properties, most programs need no changes — the same tree lays out correctly in both directions.

Reduced motion & forced colors

Motion is suppressed automatically under prefers-reduced-motion: reduce: a global rule disables every animate preset and hover utility, and motion components (Reveal, Parallax, Confetti, Backdrop, TypingIndicator, Sheet…) guard themselves with matchMedia. You can branch on it directly: 

anim = $util.media.prefersReducedMotion ? "none" : "fade-up"
Card([Text("Respectful by default")], { animate: anim })

A global @media (forced-colors: active) block keeps components legible in Windows High Contrast mode — borders and focus rings switch to system colors so nothing disappears.

Auditing with axe()

The testing utilities ship an axe(node) audit that flags the most common violations — missing alt text, unnamed buttons, unlabelled inputs, duplicate ids, and bad tabindex — plus within(node) for scoped queries. Run it in a test to keep regressions out. 

import { render, axe } from "aktion-runtime/test"

const { container } = render(program)
const issues = axe(container)
expect(issues).toHaveLength(0)

Pre-ship checklist

  1. Every interactive element is reachable and operable by keyboard.
  2. Focus is visible and never trapped except intentionally (modals).
  3. All controls have accessible names.
  4. Status/error messages use the correct Toast tone (polite vs assertive).
  5. Custom theme contrast meets AA.
  6. Meaning isn’t conveyed by colour alone.
