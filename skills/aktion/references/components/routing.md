# Routing

2 components. [← back to the catalogue index](./index.md)

## When to use what

These are the library's own authoring notes — they encode the intended choice
between similar components, which the prop tables below cannot express.

- Declare routes with the `$router({...})` call form: `pages = $router({ "/": Dashboard(), "/orders/:id": OrderDetail({ id: params.id }), default: NotFound() })`. The matched arm's `params` object is in scope on the right-hand side; nest `$router` inside components for layout-preserving sub-routes.
- `Redirect(path)` is a router-aware component: returning it from a route's body navigates and unmounts the rest of the subtree.
- `NavLink(label, { to })` is a thin link wrapper that reads `route.path` and dispatches `route.navigate(to)` — use it for sidebars, navbars and breadcrumbs.
- Read URL params via `route.params.<name>` (e.g. `route.params.id` for `/users/:id`) and the current path via `route.path`.

## Reference

### NavLink

```
NavLink(label, to, variant?, exact?, icon?, prefetch?, disabled?)
```

Anchor that navigates to a route on click and stays in sync with the URL hash. Reflects `data-active="true"` (and `aria-current="page"` for assistive tech) when the current path matches `to` (set `exact=true` to require exact equality instead of prefix matching).

| prop | type / values | required | notes |
| --- | --- | --- | --- |
| `label` | `string` | **yes** | Visible link text. |
| `to` | `string` | **yes** | Target route path, e.g. "/about". |
| `variant` | `"default"` \| `"primary"` \| `"ghost"` \| `"pill"` | no | Visual variant. |
| `exact` | `boolean` | no | Match the current path exactly (default: prefix match). |
| `icon` | `string` | no | Optional Font Awesome icon name shown before the label. |
| `prefetch` | `callable` | no | Called once on first hover/focus (warm a `$query` cache for the target route). |
| `disabled` | `boolean` | no | Grey out the link and make it unclickable / unfocusable (a route the user cannot enter yet). |

### RouteView

```
RouteView(children, routeKey, animation?, duration?, scrollToTop?, announce?)
```

Wraps a router's output so the page animates whenever the route changes. Pass `routeKey: route.path` so it knows when to replay the entrance animation; `animation` is fade|fade-up|zoom|… and `duration` is ms. Works by swapping a keyed inner wrapper, so the fresh page element plays its CSS entrance on mount. On every route change it also does what a real navigation does: scrolls back to the top (`scrollToTop`, default true), moves focus to the new page so keyboard users continue from there, and announces the new route politely (`announce` overrides the announced text). Honours prefers-reduced-motion.

| prop | type / values | required | notes |
| --- | --- | --- | --- |
| `children` | `Node` | **yes** | The $router(...) result |
| `routeKey` | `string` | **yes** | Pass route.path so the view animates on change |
| `animation` | `"fade"` \| `"fade-up"` \| `"fade-down"` \| `"fade-left"` \| `"fade-right"` \| `"zoom"` \| `"slide-up"` | no |  |
| `duration` | `number` | no | Animation duration in ms (default 300) |
| `scrollToTop` | `boolean` | no | Reset the scroll position on every route change (default true) — without it a link clicked deep in a long page lands the reader mid-document |
| `announce` | `string` | no | Text read out on a route change (default: the routeKey). Pass the page title |
